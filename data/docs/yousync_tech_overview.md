
1. 개요


1.1. 서론
누구나 좋아하는 영화나 드라마의 주인공이 되어 직접 더빙에 참여하고 싶다는 상상을 해본 적이 있을 것이다. YouSync는 이러한 꿈을 현실로 만들어주는 혁신적인 서비스이다.

이 서비스는 사용자가 영상 속 배우의 목소리를 따라하며 자신의 목소리로 더빙하고, 그 결과물을 즉각적으로 확인할 수 있도록 돕는다.

YouSync는 단순한 재미를 넘어, 발음, 억양, 타이밍까지 종합적으로 분석하여 사용자에게 실질적인 피드백을 제공함으로써 더빙 실력을 향상시킬 수 있도록 지원한다.

2. YouSync 서비스 소개 및 핵심 기능


2.1. YouSync: 나만의 목소리로 영화 속 주인공 되기
YouSync는 사용자가 원하는 영상의 대사를 직접 따라 해보고 더빙본을 만들어보는 체험에 중점을 둔 온라인 더빙 웹 프로젝트이다. 

사용자는 좋아하는 영화나 드라마의 배우가 되어 직접 더빙에 참여하며 주인공이 되는 듯한 특별한 경험을 할 수 있다. 

이 서비스는 실시간 분석 서버와 연동되어 사용자의 더빙을 즉각적으로 분석하고 피드백을 제공한다. 



2.2. 음성 쉐도잉 및 실시간 분석
YouSync는 사용자가 영상 속 배우의 음성을 듣고 자신의 목소리로 따라 하는 '음성 쉐도잉'을 기반으로 한다. 

실제 영상 속 배우의 음성을 추출하고, 정확한 발화 타이밍을 인식하여 사용자의 목소리와 싱크를 맞추는 것이 핵심이다. 

단순히 알맞은 타이밍에 말하는 것을 넘어, 사용자가 얼마나 정확하고 유사하게 억양과 텍스트를 발음했는지 체크해주는 기능도 제공한다. 

사용자는 원하는 문장을 직접 찾아보고 영상을 재생하며, 화면에 나타나는 이벤트(단어 위 표시)를 통해 언제 어떤 단어를 말해야 하는지에 대한 데이터를 얻을 수 있다. 

구간 반복 기능을 통해 여러 번 쉐도잉하며 연습할 수 있다. 



2.3. 자동 더빙 및 결과 확인
음성 쉐도잉 후 녹음이 진행되면, 즉각적인 분석 단계로 이동하여 단어별로 어떤 점수를 얻었는지 시각적으로 확인할 수 있다. 

더빙 결과는 하단 스피트바에서 각 문장별 점수를 확인하고, 최종적으로 완성된 더빙본을 들어볼 수 있다. 

완성된 더빙 결과는 웹사이트에서 다시 들어볼 수 있으며, 다른 영상에 대한 더빙도 검색하여 찾아볼 수 있다. 

만약 원하는 영상이 존재하지 않는다면, 요청 페이지를 통해 관리자에게 영상 URL을 보내 생성해달라고 요청할 수 있다. 



2.4. 특별한 기능: 듀엣 기능
YouSync는 '듀엣'이라는 특별한 기능을 통해 좋아하는 상대와 마치 대화하듯이 실제 영상 속에 들어간 것과 같은 몰입감을 제공한다. 



3. 기술적 챌린지 및 해결 방안


3.1. 발화 타이밍 및 싱크 문제 해결
문제점:

실제 영상 속 배우의 음성에서 단어 단위의 MFCC(Mel-Frequency Cepstral Coefficients, 음성의 특징을 나타내는 지표)를 추출하는 과정에서 발화 타이밍이 어긋나는 오류가 발생했다. 

이로 인해 실제 발화 타이밍이 아닌, 어긋난 형태로 데이터가 추출되는 문제가 있었다. 

또한, 영상 재생 직후 getCurrentTime() 함수를 사용했을 때 영상의 현재 시간과 시간이 불일치하는 문제가 발생했다. 

해결 방안:

Whisper 모델에서 추출된 텍스트를 발음 교정 및 발음 추출 기호 방식인 MFA(Montreal Forced Aligner)로 보정했다. 

동일한 음성을 두 가지 방식으로 분석하여 상호 교차되는 부분을 윈도우 알고리즘으로 먼저 추출했다. 

이를 통해 배우의 발음 안을 뽑아내고, 해당 타임 내에 실제 음성 데이터가 존재하는지 확인하여 대사를 완성할 수 있었다. 

영상 재생 직후 100ms 간격으로 3회 시간을 측정하여 변동이 없으면 렉으로 간주하고 앞부분 오디오를 제거하는 방식으로 영상과 사용자의 음성을 정확히 동기화했다. 

영상 속 배경음과 배우 음성을 분리하고, 사용자 음성의 문장 데이터를 추출하여 Whisper와 MFA 모델을 통해 음소 단위 단어 데이터를 추출함으로써 정확한 발화 타이밍을 추출했다. 



3.2. 음성 인식 및 발음 정확도 문제 해결
문제점:

'Hallucination' 현상으로 인해 존재하지 않는 문장이 실제 있는 것처럼 인식되는 문제가 발생했다. 

음성 인식 시 단어 단위로 분석했기 때문에, 단어의 순서가 다르더라도 결과가 똑같이 나오는 문제가 있었다. 

텍스트가 겹친다는 이유만으로 발음이 아예 다른 단어에도 가점이 들어가는 문제가 있었다. 

해결 방안:

Whisper 모델에서 추출된 텍스트를 MFA로 보정하는 방식을 사용했다. 

기존의 단어 단위 분석에서 더 잘게 쪼개진 프레임 단위로 분석하고, 각 프레임 단위로 싱크 타임이 맞지 않으면 감점을 주지 않는 방식으로 개선했다. 

ACS(Acoustic Chinese Segmentation) 알고리즘을 추가하여 분석의 보도화를 더했다. 

MFCC(Mel-Frequency Cepstral Coefficients)라는 음향적 특성을 추출하여 음성 데이터의 유사도를 비교하는 방식을 사용했다. 이는 음향적 특성을 제거하고 발음 특성만 남기는 데 중요하다고 판단했기 때문이다. 



3.3. 녹음 싱크 오류 및 데이터 전송 문제 해결
문제점:

사용자가 녹음을 시작한 이후 브라우저나 영상 오류로 인해 녹음 시간이 실제 타이밍보다 길게 녹음되는 경우, 분석 결과를 올바르게 볼 수 없었다. 

MediaRecorder 지연으로 인해 렉, 영상 멈춤, 타이밍 불일치, 녹음 대사 뒷부분 잘림 등의 현상이 발생했다. 

해결 방안:

두 개의 타이머를 사용하여 분석 로딩 상태를 특정 타이머 임계값 아래 있는 시간은 브라우저 타임으로 간주하고, 실제 음성에서 잘라서 분석 서버로 보냈다. 

음성 슬라이싱과 Whisper.cpp, librosa 라이브러리를 활용하여 문장당 분석 결과를 제공하고, 1~2초 내 사용자 경험을 개선했다. 

영상 재생 직후 getCurrentTime() 함수를 100ms 간격으로 3회 측정하여 시간 변동이 없으면 렉으로 간주하고 앞부분 오디오를 제거하여 영상과 사용자의 음성을 정확히 동기화했다. 



3.4. 기술 스택 및 아키텍처
주요 기술:

Whisper STT (Speech-To-Text)를 활용하여 음성을 텍스트로 변환하고 타임스탬프를 추출한다. 

MFA(Montreal Forced Aligner)를 사용하여 음성 데이터를 분석하고 발음 정확도를 평가한다. 

MFCC(Mel-Frequency Cepstral Coefficients)를 사용하여 음성의 특징을 추출하고 유사도를 비교한다. 

프레임 단위 분석(25ms)을 통해 음성의 미세한 변화까지 잡아낸다. 

서버 및 API:

FastAPI를 사용하여 REST API를 구축했다. 

Pydantic Schema를 사용하여 데이터 유효성을 검증한다. 

PostgreSQL 데이터베이스를 사용하며, TOKEN, SCRIPT, SCRIPT_WORD 등의 테이블을 설계했다. 

AWS S3를 사용하여 음성 데이터 및 분석 결과를 저장한다. 

비동기 처리:

FBackgroundTasks와 ThreadPoolExecutor를 활용하여 비동기 작업을 처리한다. 

SSE(Server-Sent Events)를 통해 실시간으로 분석 결과를 사용자에게 전달한다. 



3.5. 사용자 경험 개선 노력
전처리 시간 단축:

기존에는 스크립트 분석에 20~30초가 소요되었으나, 음성 슬라이싱 및 Whisper.cpp + librosa 활용으로 문장당 분석 결과를 1~2초 내에 제공하여 사용자 경험을 개선했다. 

녹음 데이터 전송 최적화:

MediaRecorder 지연으로 인한 문제를 해결하기 위해 영상 재생 직후 시간 동기화 및 앞부분 오디오 제거 방식을 적용했다. 

발화 타이밍 정확도 향상:

Whisper와 MFA 모델을 결합하여 음소 단위 단어 데이터를 추출하고, 윈도우 알고리즘으로 결합하여 정확한 발화 타이밍을 추출했다. 

Whisper와 MFA 모델의 분석 결과는 ±0.1초의 오차 범위와 80%의 정확도를 목표로 한다.
